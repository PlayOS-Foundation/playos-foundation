Definition

What "public MVP" means

The first meaningful PlayOS MVP is complete when all of these are true on physical ROG Ally hardware.

  1. ROG Ally boots directly from UEFI into PlayOS.
  2. Linux kernel + initramfs are available as a UEFI-bootable EFI artifact.
  3. playos-init runs as PID 1.
  4. playos-compositor permanently owns DRM/KMS and the Wayland session.
  5. playos-shell remains alive as the persistent controller-first UI.
  6. Compositor uses wlroots with AMDGPU, DRM/KMS, GBM, EGL, and Mesa.
  7. Shell renders through Wayland using the Raylib PlayOS backend.
  8. Shell and sample game consume the public playos-platform-api C ABI.
  9. Trusted launch, lifecycle transport, and compositor-control remain internal to playos-runtime.
  10. Shell requests game launch; playos-init spawns and supervises it.
  11. Compositor waits for the game's first valid frame before switching foreground.
  12. Game renders with hardware acceleration and receives controller input.
  13. Reserved System button returns to PlayOS UI and backgrounds/pauses the game.
  14. Resume returns to the same running game without restarting it.
  15. Game outputs audio through ALSA.
  16. Clean exit and crash both return safely to the existing shell.
  17. Games and saves persist on a separate ext4 partition.
  18. System image is immutable.
  19. Recovery mode usable without accelerated graphics.

Process

Execution rules

The rules that keep the delivery plan honest and the spec authoritative.

  1. Sprints follow dependency order unless an ADR explicitly changes the sequence.
  2. A sprint begins only after its required predecessor exit criteria are satisfied.
  3. Each sprint must end with a demonstrable and testable system outcome.
  4. Architecture changes discovered during implementation must be captured in playos-spec.
  5. Cross-sprint API changes require a version bump and compatibility review.
After MVP

Post-MVP roadmap

Features are added only after the core console lifecycle is stable and shipped.

Tier 1

Near-term · v0.2.x

  • Wi-Fi (playos-net)Network access for store downloads, cloud saves, and updates.
  • Touch + On-Screen KeyboardTouch forwarding and a single system OSK for text entry.
  • SSH Developer Mode (Dropbear)Remote debugging — opt-in only, absent from retail builds.
  • Input Service (playos-input)Controller remapping, gyro, haptics, and multi-controller assignment.
  • Full Suspend/ResumeS3 or s2idle with reliable resume, shipped only after AMD firmware validation.
  • Rear and Special ButtonsMap macro/custom buttons to logical PlayOS actions.
Tier 2

Medium-term · v0.3.x

  • Dedicated Audio ServiceMixing and notifications layered over game audio.
  • BluetoothWireless controllers, headsets, and keyboards.
  • Screenshots and Screen RecordingCapture with explicit policy guardrails.
  • Vulkan Support (RADV / ANV)Modern Vulkan games on AMD and Intel.
  • NVIDIA Backend (Nouveau + NVK + Zink)Third-vendor portability proof on the open-source stack.
  • PPSSPP (PSP) Sample via libretroReal, redistributable game payload proving the sample/SDK story.
  • VRR and HDRHigh-refresh and HDR display support.
  • Game Developer SDK (playos-sdk)Build PlayOS games from a regular Linux host.
Tier 3

Long-term · v1.0+

  • Cloud Saves and User AccountsSave portability across devices and an online game library.
  • Store + Download ManagerBrowse, install, and update games.
  • Signed .play Content PackagesIntegrity-verified, atomic installs.
  • Delta UpdatesSmaller incremental game and system updates.
  • Multiple Local User ProfilesPer-user settings, saves, and libraries.
  • External Display ProfilesDocking and TV output.
  • Telemetry (Opt-In Only)Anonymous, with explicit user consent.
  • Performance Overlay (In-Game HUD)FPS, GPU/CPU usage, and temperatures.
Out of scope

Not on the roadmap

Explicitly out of scope for PlayOS, even post-MVP.

  • General-purpose Linux desktop environment
  • X11 / Xwayland
  • Browser-based shell or WebAssembly runtime
  • Multi-GPU or hybrid-graphics rendering
  • Running multiple games simultaneously
  • Cloud gaming (streaming from a remote server)
  • Custom GPU driver or OpenGL implementation
